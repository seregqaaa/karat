# ЛУЧ-МК: показания в 1 клик

Просмотр посуточных архивов **.K20** теплосчётчиков «КАРАТ», считанных пультом
[ЛУЧ-МК (КАРАТ-913)](https://www.karat-npo.com/upload/iblock/7e6/%D0%9F%D1%83%D0%BB%D1%8C%D1%82%20%D0%BF%D0%B5%D1%80%D0%B5%D0%BD%D0%BE%D1%81%D0%B0%20%D0%B4%D0%B0%D0%BD%D0%BD%D1%8B%D1%85%20%D0%9A%D0%90%D0%A0%D0%90%D0%A2-913%20%20%D0%9B%D1%83%D1%87-%D0%9C%D0%9A%20%D1%80%D1%83%D0%BA%D0%BE%D0%B2%D0%BE%D0%B4%D1%81%D1%82%D0%B2%D0%BE.pdf),
и выгрузка отчёта в Excel — прямо в браузере, без установки «КАРАТ-Экспресс».

**Работает здесь → https://seregqaaa.github.io/karat/**

Всё считается на вашем устройстве: файлы никуда не загружаются, сервера у
проекта нет. После первого открытия страница работает офлайн (PWA).

## Как пользоваться

1. Считайте архив прибора пультом ЛУЧ-МК.
2. Перетащите файл `.K20` на страницу (или нажмите «Выбрать файл»).
3. Проверьте период и нажмите «Сохранить в Excel».

Кнопка «Посмотреть на примере» показывает интерфейс на демонстрационных данных
без файла.

## Что умеет

- Таблица показаний по дням: подача/обратка, объёмы, ΔT, тепло, наработка.
- Причины ненаработки (флаги `Er0`, например `Bat` — разряд батареи) попадают
  в Excel-отчёт колонкой «Причина ненаработки»; в таблице эти флаги скрыты.
- Выбор периода, быстрый диапазон «За последний месяц» (ровно месяц,
  заканчивающийся последними сутками архива), сортировка по любой колонке —
  мышью и с клавиатуры, итоги за период.
- Excel-отчёт в формате выгрузки оригинальной программы: те же колонки,
  заголовок с прибором и номером, строка с номером прибора, итоговая строка.
- Дата «по» последней выгрузки запоминается (отдельно для каждого прибора, по
  заводскому номеру) — следующий отчёт продолжится со следующего дня. Если
  номер в архиве не прочитался или сохранённая дата не попадает в архив,
  показывается весь период файла.
- Установка как приложение (PWA): офлайн-кэш через service worker, тёмная
  тема, свои иконки.

### Точность — как в «КАРАТ-Экспресс»

Числа в отчёте повторяют официальную выгрузку один в один (сверка
автоматизирована — см. «Тесты»; расхождений нет). Значения округляются
каскадно от точности дисплея прибора к точности отчёта (half-up): температуры
3 → 2 знака, объёмы и массы 5 → 1, тепло и наработка 5 → 2. Округление —
целочисленное, по десятичной записи числа (без `toFixed` с его
round-half-to-even и двоичной погрешностью). Итог — сумма построчно
округлённых значений.

## Формат .K20 (кратко)

Файл — бинарная выгрузка архива прибора:

| Смещение | Содержимое |
|---|---|
| `0x02`, uint16 LE | количество записей |
| `0x39` | названия колонок — Pascal ShortString, windows-1251 |
| далее | данные колонок подряд, каждая — массив float64 LE |
| данные + 128 байт | метаданные: прибор, описание архива, заводской номер |

Дата — Delphi `TDateTime` (дни от 30.12.1899). Колонки `Er0`, `Er1`, … —
битовые флаги причин ненаработки, упакованные во float32.

Парсер не привязан к набору колонок ЭЛЬФ: имена и их число читаются из самого
файла, класс величины определяется по обозначению (T/t — температура, V —
объём, G — масса, Q — тепло, P — давление, приставка `d` — разность, `Er*` —
флаги). Посуточные архивы многоканальных приборов той же линейки в этом же
контейнере разбираются без правок кода; заголовок и размеры проверяются, записи
с повреждёнными датами отбрасываются с пометкой, кольцевой буфер упорядочивается
по дате. Архив с повторяющимися именами колонок отвергается: значения хранятся
по имени, и повтор молча подменял бы данные соседней колонки. При ошибке разбора приложение предложит сохранить диагностический
файл — приложите его к вопросу, если ваш прибор не читается.

## Устройство проекта

Сборки нет — то, что лежит в репозитории, то и раздаётся браузеру:

| Файл | Что внутри |
|---|---|
| `index.html` | разметка, стили и слой интерфейса (экраны, таблица, период) |
| `k20.core.js` | ядро без DOM: разбор `.K20`, округление, сборка строк отчёта |
| `xlsx.write.js` | запись `.xlsx` (~14 КБ вместо 880 КБ SheetJS) со своим zip |
| `sw.js`, `manifest.json` | офлайн-кэш и установка как приложения |

Тесты подключают `k20.core.js` и `xlsx.write.js` теми же файлами, что и
страница, — проверяется ровно исполняемый код.

Версий две, и обе поднимаются одним коммитом: `CACHE` в `sw.js` (иначе
установленные PWA останутся на старой копии) и `K20_VER` в `k20.core.js` (он
попадает в диагностический файл — по нему видно, какая сборка его сформировала).

Страница подключает `k20.core.js` и `xlsx.write.js` обычными `<script src>`,
без модулей ES: имена ядра лежат в `window`, и это осознанно — так их может
переопределить сторонний скрипт, подключённый после страницы. Если такой файл
отсутствует, страница говорит об этом прямо, а не ломается на первом действии.
Любая сборка, которая раскладывает страницу по своему списку файлов, должна
класть рядом оба.

## Тесты

```bash
node tests/run.mjs
```

Синтетические архивы (включая двухканальный прибор, перемешанный кольцевой
буфер, NaN и битые даты), граничные случаи ядра (повтор имени колонки, колонка
`__proto__`, отсутствующий хвост метаданных, пустой период, арифметика месяца),
фазз повреждённых и мусорных файлов (~650 проб), сверка округления с
python-референсом (`decimal`, `ROUND_HALF_UP`) — и, при наличии каталога
`tests/private/` с реальными архивами и выгрузками «КАРАТ-Экспресс», поячеечная
сверка отчёта с оригиналом плюс golden-снапшоты. `tests/private/` в git не
попадает: реальные архивы содержат заводской номер прибора. Тот же прогон
выполняется в GitHub Actions на каждый пуш.

Отдельный сьют проверяет сам файл отчёта: .xlsx распаковывается собственным
распаковщиком (структура пакета, CRC каждой записи, поячеечная сверка данных,
ширины колонок, отсутствие лишних ячеек), валидируется python-ом (`zipfile` +
`xml.etree`, `openpyxl`) и читается обратно полным SheetJS
(`tests/xlsx.full.dev.js`) — и через `write()`, и через `writeFile()`, со сжатием
и без. Именно на этих тестах — без их правки — библиотека записи была заменена
с 880-килобайтного SheetJS на `xlsx.write.js`.

Переменные окружения прогона: `PYTHON` — чем звать интерпретатор (по умолчанию
`python3`; отсутствие python пропускает две сверки, любая другая его ошибка
валит прогон), `UPDATE_GOLDEN=1` — разрешить запись отсутствующих
golden-снапшотов (без неё их отсутствие — провал, чтобы регрессия не стала
эталоном молча).

## Запуск локально

Достаточно открыть `index.html` — рядом должны лежать `k20.core.js` и
`xlsx.write.js`. Сторонних скриптов, шрифтов и CDN на странице нет: сама она
не запрашивает ничего за пределами своего каталога. Для service worker и
установки PWA нужен `http(s)`, например:

```bash
python3 -m http.server 8000
```
