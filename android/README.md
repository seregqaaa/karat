# KARAT — нативное Android-приложение (Kotlin)

Приложение для пульта ЛУЧ-МК: находит архив `.k20` на подключённом пульте (или
файл выбирается вручную), показывает таблицу за выбранный период и отправляет
отчёт `.xlsx` на почту через Yandex Cloud Function.

Версия 3.0 переписана с WebView-обёртки (v2.x, `index.html` в assets) на
нативный Kotlin. Веб-версия в корне репозитория живёт своей жизнью и остаётся
источником истины для браузера/PWA.

## Что на экранах

Только элементы управления, без пояснительных подписей.

- **Главный**: «Разрешить доступ» (пока не выдан SAF-грант), «Выбрать файл»,
  индикатор поиска, «Повторить поиск» (если пульт не нашёлся), кнопки выбора
  прибора — если архивов несколько.
- **Приём файла извне**: приложение зарегистрировано в системном «Поделиться»
  (`ACTION_SEND` / `ACTION_SEND_MULTIPLE`, `application/*`). Выбранный в
  проводнике `.k20` открывается тем же кодом, что и файл из «Выбрать файл»
  (`openUris()` — единственная точка входа), несколько файлов сразу —
  предлагаются кнопками выбора. Если КАРАТ мешает в списке «Поделиться» для
  других документов, сузьте `android:mimeType` до
  `application/octet-stream` в `apk/AndroidManifest.xml` — по правилам
  сопоставления Android этого хватает и для отправок с типом `*/*`.
- **Таблица**: прибор и заводской номер, даты «С»/«По» (системный
  date-picker), «Отправить», «Другой файл», крупный итог по последней колонке
  (Q1под) и сама таблица с закреплённой строкой «Итого». Колонка `Er0` в
  таблицу не выводится — она есть только в Excel-отчёте («Причина
  ненаработки»).
- Ошибки — во всплывающих диалогах.

## Структура

```
src/core/K20.kt      разбор .k20 (порт K20CORE v11 из index.html)
src/core/Round.kt    каскадное округление half-up «как в КАРАТ-Экспресс»
src/core/Report.kt   строки отчёта (формат выгрузки оригинальной программы)
src/core/Xlsx.kt     запись .xlsx (порт xlsx.write.js)
src/app/MainActivity.kt  UI, SAF-сканирование пульта, отправка
src/app/Config.kt    SEND_URL и SEND_ADDRESS — в git не попадает
src/test/TestMain.kt CLI для JVM-проверок ядра
tests/               сверка с эталонами и с JS-ядром + фазз
apk/                 манифест, ресурсы и apktool.yml (упаковка без Gradle)
proguard.cfg         шринк kotlin-stdlib
build.sh             сборка целиком
```

Ядро (`src/core`) не зависит от Android — те же классы гоняются на JVM в
тестах. `MainActivity` — единственный файл, знающий про Android API.

## Сборка

```bash
cd android
cp src/app/Config.example.kt src/app/Config.kt   # подставить URL и адрес
bash build.sh                                    # → out/KARAT-3.1.apk
bash build.sh test                               # только проверки ядра
```

Нужен JDK 17+, `python3`, `curl`, `git` и интернет: инструменты (kotlinc из
npm, apktool, ProGuard, uber-apk-signer, android.jar, dx из исходников AOSP)
скачиваются в `.tools/` при первом запуске. Android Studio, Gradle и Google
Maven не нужны — последний из некоторых сетей и недоступен. На Windows —
через WSL или Git Bash.

Подпись берётся из `../keys/apk.crt` + `../keys/apk.key` (тот же сертификат,
что у v2.x, поэтому APK ставится обновлением поверх — данные и запомненные
даты выгрузок сохраняются).

## Почему ProGuard обязателен

Без шринка в dex уезжает вся `kotlin-stdlib`: 2.7 МБ dex и APK ~810 КБ.
ProGuard оставляет только достижимые 149 классов — dex 160 КБ, APK ~78 КБ.
Режим намеренно `-dontoptimize -dontobfuscate`: шринкнутый байткод должен
оставаться пригодным для прогона теми же тестами. **Не добавляйте
`-dontpreverify`** — без `StackMapTable` шринкнутый код не запускается на JVM
(`VerifyError: Expecting a stackmap frame`); на размер dex этот атрибут не
влияет, dx его отбрасывает.

## Тесты

`bash build.sh test` (или `K20_JAR=… python3 tests/check_core.py`) проверяет:

- **golden-снапшоты** — разбор + округление всех строк реальных архивов
  сверяется с `tests/private/golden/*.json` (снимки JS-ядра);
- **округление** — 4108 случаев, включая «злые» половинки (0.755, 1.005,
  0.955), против python `decimal` + `ROUND_HALF_UP`;
- **отчёты** — собранный `.xlsx` сверяется поячеечно с эталонными выгрузками
  «КАРАТ-Экспресс» (`tests/private/etalon_*.xlsx`) и, как арбитр паритета, с
  файлом, собранным JS-ядром веб-версии (`tests/js_build.mjs`, нужен node).

Нужен каталог `tests/private/` из корня репозитория (реальные архивы и
эталоны, в git не публикуются).

Правки в первых двух строках эталонов (адрес в `D1`/`C1`, «Итого:» с
двоеточием, свои ширины колонок) делались вручную в Excel — сверяются
нестрого. Заголовок `D1` формируется как «`{адрес} отчет данных {месяц С}
{месяц По} {год}`» и совпадает с эталонами дословно там, где их не правили
руками.

## Что осталось от v2.x без изменений

Пакет `ru.karat.k20viewer`, minSdk/targetSdk 30, единственное разрешение
`INTERNET`, автозапуск по `USB_DEVICE_ATTACHED` с фильтром на mass storage,
доступ к файлам через Storage Access Framework (`OPEN_DOCUMENT_TREE` +
обход `archives/{номер}/`), `SharedPreferences("k20")` с ключами
`lastExportTo:{серийник}` и стартовой датой 23.06.2026 до первой отправки.
